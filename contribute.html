Ways to Contribute

Contribution is bigger than writing code.

Open-source communities need different kinds of knowledge and work. Contribute where your skills, experience, or interests can provide useful value.

01

Code

Build features, fix bugs, improve existing software, write tests, and create useful tools.

02

Documentation

Improve README files, technical guides, explanations, examples, references, and project documentation.

03

Learning Resources

Share useful tutorials, notes, exercises, references, demonstrations, and practical learning material.

04

Research

Contribute research questions, experiments, analysis, datasets, technical reports, prototypes, and findings.

05

Security Knowledge

Contribute responsible security research, defensive knowledge, practical labs, technical writeups, and security learning resources.

06

Design & Engineering

Improve interfaces, architecture, diagrams, workflows, developer experience, and technical systems.

07

Testing & Review

Test software, reproduce problems, review contributions, identify improvements, and provide constructive technical feedback.

08

Community Support

Help with mentorship, technical discussions, community resources, activities, and the infrastructure that supports contributors.

Contribution Path

From discovering a project to maintaining the work.

Good contributions begin with understanding. The process should give contributors enough context to make useful changes and give other contributors an opportunity to review and improve the work.

01

Discover

Find a repository, resource, project, research topic, or technical problem that interests you.

02

Understand

Read the available documentation and understand the existing work before making changes.

03

Choose

Select a contribution that matches your skills, interests, and available time.

04

Discuss

For larger or unclear changes, discuss the idea with relevant contributors before investing significant work.

05

Contribute

Submit code, documentation, research, resources, testing, design, or another useful contribution.

06

Review

Give other contributors an opportunity to examine the work and provide constructive technical feedback.

07

Improve

Respond to feedback, correct problems, and improve the contribution before it becomes part of the shared work.

08

Maintain

Continue improving useful work after its initial contribution and help future contributors understand it.

Good First Practice

Understand before you change.

Read the repository documentation, inspect the existing work, understand the problem, and then make a focused contribution.

Quality

Useful contributions should be clear, responsible, and maintainable.

TCOSC values the quality of shared technical work, not simply the number of contributions made.

Useful

Contributions should solve a genuine problem, improve existing work, or provide meaningful value to others.

Clear

Code, documentation, research, and other contributions should be understandable to the people who will use or maintain them.

Reproducible

Where appropriate, technical work should contain enough information for others to understand, test, or reproduce it.

Reviewed

Important contributions should be open to constructive technical review and improvement.

Maintainable

Contributors should consider how their work will be understood and maintained after the initial contribution.

Attributed

Give appropriate credit to people whose code, ideas, research, resources, or other work you use.

New Contributors

You can start before you know everything.

Git and GitHub are skills that can be learned through practice. Your first contribution does not need to be a large software feature.

Read

Explore an existing repository and understand what it is trying to accomplish.

Document

Improve an explanation, example, README, or other piece of documentation.

Test

Try software, reproduce a problem, and provide useful information about what happened.

Ask

Ask a clear technical question when something in a project is difficult to understand.

Learn Git

Build your Git and GitHub skills gradually through real project work.

Make Your First Contribution

Start with a focused improvement that you can understand, test, and explain.

Responsibility

Contribute responsibly.

Open-source work affects other people and systems. Contributors should understand the permissions, licenses, privacy considerations, security implications, and responsibilities associated with their work.

Respect Systems

Do not access, test, modify, or interfere with systems without appropriate authorization.

Respect People

Protect the privacy, dignity, safety, and work of other community participants.

Respect Licenses

Understand and follow the licenses and attribution requirements associated with work you use or contribute.

Share Responsibly

Consider the potential impact of publishing sensitive technical information, security research, or other potentially harmful material.
